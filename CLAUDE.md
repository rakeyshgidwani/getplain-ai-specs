# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is **getplain-ai-specs**, a specification-only repository containing YAML/JSON configurations that drive code generation for the plain AI platform. This repository contains no executable code—all files are declarative specs consumed by various code generators.

## Architecture

The platform uses a microservices architecture with NYC-themed naming. Each directory represents a different domain:

### Core Services

- **grand-central** - Central orchestration and configuration hub. Defines environments (dev, qa, stg, prv, prd), repo mappings, and infrastructure profiles. References all hudson-river databases.

- **hudson-river** - Data layer specifications. Contains database schemas and API configurations for:
  - Core: UserDB, OrgDB, ProjectDB
  - Output: ArtifactDB, DeploymentDB
  - ThirdParty: IntegrationDB, SecretsDB
  - Products: ProductDB

- **broadway-authz** - Authorization service using SpiceDB. Defines RBAC schema with hierarchical resources (organization → project → document) and role-based permissions.

- **skyline-web** - Frontend web application specs. Contains:
  - Routes configuration (public vs authenticated pages)
  - Screen definitions (declarative UI components)
  - Navigation configs (top nav, user profile menu)
  - State management (user context, workspace context)
  - OpenAPI integrations for backend services

- **madison-agents** - AI agent configurations using CrewAI patterns. Defines agents with roles, goals, tools, and policies. Default LLM: `anthropic/claude-sonnet-4.5`.

- **holland-connectors** - Third-party API connector specifications. Layered architecture (layer0-3) for OpenAPI-based integrations (OpenAI, Middesk, Dome, RunPod).

- **union-square** - Deployment orchestration. Configures build/deploy workflows via the `hudson` CLI.

### Key Patterns

**Infrastructure Profiles**: `budget` for non-prod, `strategic` for prod (defined in grand-central)

**Environment Progression**: dev → qa → stg → prv → prd

**Component Types**:
- `service` - Deployable API or worker services
- `postgres` / `redis` - Datastore definitions
- Traits: `lifecycle`, `env-binding` for environment-specific configs

**Screen Definitions** (skyline-web): Declarative UI using component types like `PageHeader`, `ComponentGrid`, `StatCard`, `DataTable`, `CardList`. Data fetching via `source` references to OpenAPI operations.

## Working with Specs

All changes in this repository affect generated code in the main `getplain.ai` repository. Specs follow these conventions:

- **Config files**: `specs/config/*.json` - Service-level configuration
- **Infra files**: `specs/infra/*.yaml` - Infrastructure definitions (generated by grand-central-core)
- **App files**: `specs/app/*.yaml` or `*.yml` - Application-level specs (routes, screens, agents)

When modifying RBAC in `broadway-authz/specs/config/broadway.authz.rbac.schema.yaml`:
- Resources define the hierarchy (parent-child relationships)
- Roles map to relations on scope resources
- Permissions reference roles, not direct relations
- Inheritance rules define permission flow down the hierarchy
